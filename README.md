# 翡翠山城别墅区信息公示

基于 GitHub Pages 的静态托管特性，结合小区公共决策的敏感性，建议从功能极简、信息透明、责任边界清晰三个原则来设计。

## 一、功能板块划分

GitHub Pages 是静态站点，无法运行后端服务，因此天然适合"只读公示"型架构，避免复杂的用户交互带来的法律风险。
**核心板块**

| 板块        | 内容                      | 设计要点                       |
| --------- | ----------------------- | -------------------------- |
| **首页公告**  | 最新业主大会决议、会议通知、紧急公示      | 按时间倒序，突出"最新"和"已生效"标识       |
| **决策公示库** | 历次业主大会表决结果、会议纪要、投票统计    | 按年度/议题分类，附会议时间、参会比例、表决结果   |
| **财务公开**  | 公共收益收支明细、维修资金使用情况、预算执行表 | **关键：只展示汇总数据，不公开具体业主缴费记录** |
| **规章制度**  | 业主管理规约、业主大会议事规则、业委会工作规则 | 提供 PDF 下载，标注生效日期和版本号       |
| **项目公示**  | 小区改造、维修工程方案、招投标信息、施工进度  | 附方案文本、预算、工期、承建方资质（公开信息）    |
| **联系方式**  | 业委会办公地址、接待时间、物业监督电话     | 只公开**公务联系方式**，不公开个人手机号/微信  |
| **历史归档**  | 往届业委会交接资料、历史决议存档        | 确保信息连续性，避免"人走茶凉"信息断层       |

**建议不做的功能**

- ❌ 业主留言板 / 评论功能（避免言论失控、诽谤风险）
- ❌ 在线投票 / 表决系统（GitHub Pages 无法做身份验证，投票结果无法律效力，反而引发争议）
- ❌ 业主名录 / 房产信息查询（严重个人信息泄露风险）
- ❌ 实时聊天 / 论坛（内容不可控）

## 二、法律风险规避要点

小区公共决策网站的核心法律风险集中在个人信息保护、名誉侵权、决议效力争议三个方面。

### 1. 个人信息保护（最敏感）

严格脱敏原则：
公示投票结果时，只展示"同意/反对/弃权"的票数、面积占比，不公示具体房号、业主姓名
财务公示中，涉及业主个人缴费、欠费信息一律不上网
会议签到表、签到照片如有上传，必须对所有人脸、姓名、房号进行打码处理
不要公开任何业主的联系方式、车牌号、家庭成员信息
法律依据：《个人信息保护法》《民法典》第1034条

### 2. 内容发布边界

只发布"组织行为"结果，不发布"个人评价"：

- ✅ 可以发："业主大会于X月X日表决通过《电梯更新方案》，同意率67%"
- ❌ 不要发："某业主多次阻挠施工，素质低下"（涉嫌名誉侵权）
- ❌ 不要发："物业经理贪污"（如无司法认定，涉嫌诽谤）
- ❌ 不要发：涉及具体业主违约、欠费、违规的点名通报

**会议纪要规范**：
只记录议题、讨论要点、表决结果、后续安排
不记录"某某业主说了什么"（除非该业主明确要求记录并公开其发言）
涉及业主投诉内容的，隐去投诉人身份信息，只陈述事项和处理结果

### 3. 法律效力声明

在网站底部或关于页面，必须设置免责声明：
"本网站为**翡翠山城别墅区业主大会**设立的信息公示平台，旨在提升小区公共事务透明度。网站所载内容均为业主大会或业主委员会依法定程序形成的结果性信息，不构成对任何第三方的法律承诺。如对公示内容有异议，请通过书面形式向业主大会或相关部门提出。本网站不具备在线投票、在线表决功能，小区重大事项决策以书面签名或法律法规认可的其他表决方式为准。"
